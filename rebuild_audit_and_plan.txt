[ISSUE 1.1] Typos on "Why Choose Us" Page

- Line 95: "E-Commerse solutions"       -> Fix spelling to "E-Commerce"
- Line 103: "Web application developement" -> Fix spelling to "development"

[ISSUE 1.2] Broken Social Previews (OpenGraph og:image)
- Root Cause: metadata/defaultMetadata.js sets `url: '/images/og-image.jpg'` 
  without setting `metadataBase` in Next.js Root Layout (app/layout.tsx).
- Impact: When Next.js compiles relative URLs without `metadataBase`, it defaults 
  to `http://localhost:3000/images/og-image.jpg`. When shared on LinkedIn, Twitter/X, 
  Facebook, or WhatsApp, social cards fail to load previews.
- Additional Issue: The path `/images/og-image.jpg` does not exist in `public/` (404 Error).
- Solution: 
  1. Set `metadataBase: new URL('https://www.globalpearlventures.com')` in `app/layout.tsx`.
  2. Create a dedicated, branded 1200x630px preview image `public/og-image.png`.
  3. Use absolute canonical URLs for all page metadata.

[ISSUE 1.3] Duplicate & Bloated Image Assets in public/
- Root Cause: 
  - `Team collaboration.png` (590 KB) and `Team_collaboration.png` (590 KB) exist 
    as two separate identical files in `public/`.
  - `app/page.tsx` references `/Team collaboration.png` with an unescaped space.
  - Bloated asset sizes: `connexaLogo.png` is 7.2 MB, `web-dev-icon.gif` is 4.1 MB, 
    `cloud-devops-icon.gif` is 2.6 MB, `Five_industries.jpeg` is 830 KB.
  - Total `public/` directory size is ~25 MB!
- Solution:
  1. Delete duplicate `Team collaboration.png` and standardize on `Team_collaboration.png`.
  2. Compress `connexaLogo.png` from 7.2 MB down to ~150 KB (WebP/PNG).
  3. Convert heavy GIF animations to lightweight WebP animations or CSS/SVG graphics.

[ISSUE 1.4] Image Optimization Disabled (<img> vs <Image />)
- Root Cause: Standard HTML `<img>` tags are used in `app/page.tsx`, `components/main-nav.tsx`, 
  `components/footer.tsx`, `app/about-us/page.tsx`, `app/why-choose-us/page.tsx`, etc.
  `next.config.mjs` has `images: { unoptimized: true }` which disables automatic WebP/AVIF 
  compression and responsive scaling.
- Solution:
  1. Replace all HTML `<img>` tags with Next.js `<Image />` components.
  2. Provide proper `width`, `height`, `sizes`, `priority`, and `alt` tags.
  3. Re-enable Next.js image optimization or configure static export image loader.

[ISSUE 1.5] Cache Control & Static Asset Lifetimes
- Root Cause: Default static server/CDN cache TTL for static assets in `public/` is ~4 hours.
- Impact: Returning visitors re-download ~2.5 MB of un-cached assets on every visit.
- Solution:
  1. Configure `Cache-Control: public, max-age=31536000, immutable` headers for static 
     assets via server/deployment config (Vercel/Netlify headers or custom server).
  2. Leverage Next.js static asset hashing (`_next/static/`) for instant repeat loads.

2. SYSTEM & CODEBASE AUDIT FINDINGS
================================================================================

[ISSUE 2.1] Inconsistent Route Folder Naming
- File Path: app/Industries/
- Problem: `app/Industries/` uses a capital "I", whereas all other route folders use 
  lowercase kebab-case (`app/about-us`, `app/our-products`, `app/our-services`).
- Impact: Case-sensitive production web servers (e.g., Linux, Vercel) can cause 404 errors 
  or broken routing when navigating to `/industries`.
- Solution: Rename `app/Industries` to `app/industries`.

[ISSUE 2.2] Suppressed Build & TypeScript Errors in next.config.mjs
- File: next.config.mjs
- Lines 18-21: `eslint: { ignoreDuringBuilds: true }` and `typescript: { ignoreBuildErrors: true }`.
- Impact: Critical type errors and bugs are hidden rather than fixed.
- Actual Hidden Errors Discovered:
  1. `components/ui/sidebar.tsx`: Imports `useIsMobile` from `@/hooks/use-mobile`, 
     but the hook is exported as `useMobile`.
  2. `components/footer.tsx`: Imports non-existent/unused social icons from `lucide-react`.
  3. `app/our-products/ourProductsPage.tsx`: Ref type mismatches (`RefObject<HTMLElement | null>` 
     vs `RefObject<HTMLElement>`).
  4. Relative PNG module imports in TS files lack type declarations.
- Solution: Fix all TypeScript errors and remove error suppression flags from `next.config.mjs`.

[ISSUE 2.3] Duplicate Content & Copy-Paste Bugs
- File: app/our-products/ourProductsPage.tsx
- Lines 468-514: The **Connexa** section copies the exact description text of **Voxa** 
  and incorrectly re-uses `ref={voxaRef}` instead of its own ref.
- **AeroManage** section is commented out in `ourProductsPage.tsx` but remains active on 
  the Industries page (`industriesPage.tsx`).
- Solution: Provide distinct content for Connexa and standardize AeroManage status.

[ISSUE 2.4] Discrepancy in Form Handling
- `components/contact-form.tsx` uses a mock `setTimeout` simulation.
- `app/get-in-touch/getInTouchPage.tsx` uses `emailjs-com` directly.
- Solution: Create a single unified, validated contact form component powered by React Hook Form + Zod.

[ISSUE 2.5] Plain JavaScript Metadata Files
- Files: `metadata/*.js` (`defaultMetadata.js`, `aboutMetadata.js`, `ourServicesMetadata.js`, etc.)
- Problem: Written in plain JS without TypeScript types inside a TS project.
- Solution: Convert to `.ts` files with Next.js `Metadata` type annotations.

3. DETAILED ACTIONABLE RECOMMENDATIONS FOR THE REBUILD
================================================================================

1. ROUTING & STRUCTURE:
   - Rename `app/Industries` -> `app/industries`.
   - Standardize page file architecture across all routes.

2. PERFORMANCE & ASSETS:
   - Optimize all images in `public/` (compress `connexaLogo.png`, GIFs to WebP).
   - Deduplicate image assets.
   - Convert all `<img>` elements to Next.js `<Image />`.
   - Set 1-year immutable caching headers for static assets.

3. TYPE SAFETY & CLEAN CODE:
   - Fix all TypeScript & lint errors.
   - Remove build error suppression in `next.config.mjs`.
   - Convert `metadata/*.js` to `metadata/*.ts`.

4. UI/UX & DESIGN ENHANCEMENTS:
   - Polish responsiveness across mobile, tablet, and desktop breakpoints.
   - Standardize theme system (Tailwind color tokens, dark mode support via next-themes).
   - Improve hover states, card shadows, and micro-animations.

5. SEO & ACCESSIBILITY:
   - Configure `metadataBase` in root layout.
   - Ensure all interactive elements have proper `aria-label` attributes.
   - Include high-res `og-image.png` for social card previews.
